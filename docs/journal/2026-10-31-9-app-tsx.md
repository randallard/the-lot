# 2026-10-31 (9): App.tsx

Ryan: *"start on App.tsx."* It had 9 errors and 17 `exhaustive-deps` warnings under the strict
config. The 85 in 10-31 (6)'s first measurement dropped once ADR-0070's options and the autofixes

## The errors

- **The saved player position** (`townage-player-pos`, restored after a game): `JSON.parse`
  returned `any` straight into state. It's now `unknown`, and only an `{ x: number, z: number }`
  is restored; anything else starts from the default spawn. **This is the one runtime change:**
  corrupt storage used to restore garbage.
- **Two fire-and-forget promises** (`processAsyncResults`, `fetchPendingResults`) are marked with
  `void`, which is what they already were.
- **`onSend={handleChatSend}`**: an async handler went where `(msg) => void` was expected. It's
  now wrapped, `(message) => { void handleChatSend(message); }`.
- **The accept text's `?? "let's do this!"`** was unreachable, because `gameAcceptText` is a
  required string. Removed.
- **The assembly cutscene's timer**: an `if / else if / else if` over a three-value union, with
  `clearTimeout(t!)` at the end. It's now one conditional expression, so `t` is always assigned.

## The warnings: why `game` was "missing"

The dependency lists already named members (`[game.collectPart]`), but calling `game.collectPart()`
method-style passes `game` as `this`, so the rule wanted `game` itself. And `game` is a new object
every render (`useGameState` returns a fresh literal), so listing it would recreate the callbacks
every render and re-run two effects. The actions are all stable `useCallback`s that don't use
`this`, so they're **destructured once** (`collectPart`, `completeAssembly`, `clearOverride`,
`setPhaseOverride`, `npcWalkAway`, `clearResults`, `completeIntro`, and `launchGame` as
`enterLaunchingGame`, because the launch service's `launchGame` is also imported) and called
directly. Three more stable dependencies were listed: `setShowChatInfo` (a `useCallback` with
`[]`) ×2, and `setPhaseOverride` in `handlePlayAgainSelect`, which keeps its existing `[game]`.

Nothing re-renders or re-runs differently: every added dependency is stable.
